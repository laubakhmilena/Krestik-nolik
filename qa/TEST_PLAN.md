# Тест-план

## 1. Общая информация

**Продукт:** браузерная игра «Крестики-нолики: Новая Эра»  
**Тип:** frontend-приложение  
**Цель:** оценить функциональную корректность, удобство, адаптивность, доступность и стабильность основных пользовательских сценариев.

## 2. Цели

- проверить запуск и навигацию;
- проверить правила классических крестиков-ноликов;
- проверить победу и ничью;
- проверить счётчики и повторную игру;
- проверить режим с ботом на всех уровнях;
- проверить восстановление состояния;
- проверить переключение и сохранение тем;
- выявить критичные UI/UX и accessibility-проблемы;
- создать регрессионный набор;
- автоматизировать smoke-сценарии.

## 3. Объём

### Входит

- стартовый экран;
- главное меню;
- игра с другом;
- игра с ботом;
- Easy, Medium, Hard;
- сетка 3×3;
- победа и ничья;
- блокировка поля после завершения;
- счётчики;
- рестарт и сброс;
- выход и подтверждение;
- темы;
- локализация;
- адаптивность;
- клавиатурная навигация;
- базовая доступность;
- браузерная консоль;
- запуск через локальный сервер.

### Не входит

- backend security;
- нагрузочное тестирование;
- платежи и реклама;
- внутренние алгоритмы SDK;
- полный аудит WCAG;
- устаревшие браузеры без ES6.

## 4. Стратегия

### Функциональное тестирование

Позитивные и негативные сценарии:

- ход в свободную клетку;
- повторный клик по занятой клетке;
- ход после окончания партии;
- все победные комбинации;
- ничья;
- новая партия;
- сохранение и сброс счёта;
- переходы между экранами.

### Переходы состояний

1. Start.
2. Main menu.
3. Difficulty selection.
4. Friend game — active.
5. Friend game — finished.
6. Bot game — player turn.
7. Bot game — bot thinking.
8. Bot game — finished.
9. Exit modal.
10. Orientation overlay.

### UI/UX

- читаемость;
- размеры интерактивных элементов;
- отсутствие наложений;
- понятность статусов;
- консистентность кнопок;
- обратная связь;
- мобильные разрешения.

### Совместимость

| Платформа | Браузеры |
|---|---|
| Windows 10/11 | Chrome, Edge, Firefox |
| macOS | Chrome, Safari |
| Android | Chrome |
| iOS | Safari |

### Доступность

- управление клавиатурой;
- видимый фокус;
- accessible names;
- семантика;
- масштабирование;
- `aria-live`;
- контраст;
- отсутствие зависимости только от цвета.

### Автоматизация

Автоматизируются стабильные сценарии высокого приоритета:

- запуск;
- навигация;
- friend-mode;
- победа;
- счётчики;
- рестарт;
- модальное окно;
- тема;
- выбор сложности.

## 5. Приоритеты

| Приоритет | Описание |
|---|---|
| P0 | Приложение не запускается или игру нельзя начать |
| P1 | Нарушены правила, неверная победа/ничья |
| P2 | Ошибки счётчиков, навигации, состояния |
| P3 | UI, локализация, доступность, UX |

## 6. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---:|---:|---|
| Различия localhost и платформы | Высокая | Среднее | Проверить оба окружения |
| Асинхронный бот и flaky-тесты | Средняя | Среднее | Ждать состояние, а не таймер |
| Тема меняет символы | Высокая | Среднее | Проверять `data-symbol` |
| Landscape блокируется | Средняя | Высокое | Отдельная проверка |
| SDK недоступен локально | Высокая | Низкое | Проверить fallback |
| `localStorage` влияет на тесты | Средняя | Среднее | Очищать storage |

## 7. Критерии начала

- доступен код;
- приложение открывается через HTTP;
- определены основные сценарии;
- подготовлено окружение;
- доступна Console.

## 8. Критерии завершения

- выполнены P0/P1;
- нет Blocker/Critical;
- smoke проходит;
- функции связаны с тестами;
- дефекты воспроизводимы;
- сформирован отчёт.
